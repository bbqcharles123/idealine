## 작업 방식 (반드시 이 순서를 따를 것)

기준 문서: Notion `기준정리` 페이지 — https://app.notion.com/p/3ce2a8746cb18019b726f45a32d2e97e
(위치: 개인 홈 / 프롬프팅 관련 내용정리 / 기준정리)

AI가 호출되는 곳마다 아래 3열로 기준을 정리한다.

| 열 | 의미 |
|---|---|
| 무엇을 받아야 하는지 | user/system 프롬프트에 무엇을 제공해야 원하는 결과가 나오는지 |
| 무엇을 만들어야 하는지 | AI 응답으로 기대하는 산출물 |
| 무엇이 실패로 볼 수 있는지 | 실제 데이터 로그에서 발견한 원치 않는 결과 패턴 |

이어서 "보완할 점"을 두 갈래로 나눠 작성한다.

1. **연결/누락 오류 검증** — 호출 간 데이터가 끊기거나 조용히 유실되는 심각한 오류가 있는지, 실제 로그(콘솔 경고 포함)로 확인. 있으면 이게 최우선 — 서비스가 깨지는 문제라 프롬프트 튜닝보다 먼저 고친다.
2. **프롬프트 문장 개선** — 데이터는 제대로 오가지만 지시가 원하는 응답을 못 끌어내는 경우. 실데이터 근거(입력 스타일별 비교 등)를 남기고 나서 문장을 고친다.

**우선순위**: ①연결/누락 오류(치명적) → ②응답 품질 개선(튜닝). 한 호출 지점의 기준정리를 끝내고 나서 다음 지점으로 넘어간다 — 여러 지점을 한 번에 고치려 하지 않는다.

**수정 시 규칙**: 문체·작성 규칙처럼 여러 조정이 필요한 부분과, 명확한 구조적 결함(예: 특정 정보가 프롬프트에 아예 안 들어감)은 분리해서 하나씩만 고친다. 요청받지 않은 범위까지 같이 고치지 않는다.

## 데이터 수집 방법

브라우저에서 실제로 입력창에 주제를 넣어보며 `openaiClient.js`가 콘솔에 찍는 `[AI ▶ 요청]`/`[AI ◀ 응답]` 로그를 확인한다. 서로 다른 스타일의 주제를 섞어 쓴다.

- 짧은 단어 (예: "1인 가구")
- 중간 문장 (예: "대학생 자취 생활을 돕는 서비스")
- 긴 추상 문장 (예: "ai 기술 기반 혁신적인 제품 및 서비스 아이디어")

지난 세션에서 쓴 실제 로그 4세트가 있었으나 업로드 파일이라 이 저장소에는 없다 — 새 세션에서는 필요한 호출 지점마다 새로 데이터를 수집해야 한다.

## 완료된 항목

### 1. 시작카드 생성 `seed_content` (`Gd project/src/ai/seedCard.js`)

**상태: 기준정리·문제 분석만 완료, 프롬프트 코드 수정은 미착수**

- 확인된 문제
  - 입력 주제를 그대로/거의 그대로 복사해 제목으로 재사용 (예: "중고 육아용품 대여/순환" → "중고 육아용품 순환 대여 플랫폼") — 분야 힌트와 상황/제약 힌트를 구분하지 못함
  - system/user 프롬프트가 입력 스타일(짧은 단어/중간 문장/추상 문장)과 무관하게 완전히 고정되어 있어, 4개 스타일 모두 "타깃+문제+해결" 동일 패턴으로 수렴
- 연결/누락 오류 검증 결과: **없음.** `generateSeedCard`는 `generateSeedContent → generateUxEval`로 순차 호출되며 생성된 title/description이 그대로 다음 호출에 들어가는 것을 로그로 확인함
- **다음에 할 일**: system 프롬프트에 "입력 문구를 그대로 재사용하지 말고 분야/상황 힌트로 재해석하라"는 규칙과, 입력 스타일별 대응 지침을 추가하는 프롬프트 문장 수정 (아직 코드 변경 없음)

### 2. 확장하기 2단계 선택지 생성 `tool_examples` (`Gd project/src/ai/deriveCard.js` — `generateToolExamples`)

**상태: 완료, 커밋됨**

- 확인된 문제: 이 호출은 `frameworkDesc.js`의 방향성 reasoning(예: "세 도구 모두 기존에 존재하는 요소를 건드리는 방식")만 받고, 개별 도구(제거/대체/분할·분리)가 서로 뭐가 다른지는 프롬프트에 없었음 → 같은 방향성 안 예시 3개가 비슷한 문장 구조로 수렴
- 수정 내용: 이미 존재하지만 질문 생성(`generateQuestion`)에서만 쓰이던 `toolLayerDesc.js`의 `TOOL_LAYER_DESC`(도구별 정의)를 `[이 방향성의 도구 목록]` 섹션에 함께 주입 — 도구 이름만 나열하던 것을 `- 도구명: 정의` 형태로 변경
- 커밋: `f39a8c6` (`experiment/layer-stack-node-v2`)
- **남겨둔 것 (의도적으로 이번엔 손대지 않음)**: 문장 구조가 "~하여 ~함으로써 ~할 수 있습니다"로 반복되는 문체 문제. Notion 기준정리에는 반영해뒀지만 **어투(종결 스타일) 통일과 문장 구조(도구 특성 반영)는 별개 축**이라는 점을 명확히 구분해서 기록해둠 — 어투는 통일 유지, 문장 구조만 도구별로 달라져야 한다는 결론
- `bccData.js`는 확인 결과 화면에 안 쓰이는 죽은 데이터(사람이 미리 써둔 도구별 example/question, AI 연동 전 테스트용)로 판단 — **이번 프롬프트 개선에는 활용하지 않기로 결정함**. `label`/`tool.name`/`tool.icon`만 UI에서 실사용 중.

## 아직 기준정리 안 된 대상 (남은 작업)

`Gd project/src/ai/deriveCard.js` 안에 있는 나머지 호출들. 파일 하나 안에 다 있으니 코드 확인은 빠르게 가능하고, 각각 실 데이터 수집이 필요함.

| 호출 | 함수 | 현재 알려진 것 |
|---|---|---|
| 확장 3단계 / 변형 2단계 질문 생성 | `generateQuestion` | 기준정리 미착수. `TOOL_LAYER_DESC` + `getFrameworkContext`를 이미 받고 있음(2단계 예시보다 정보가 많음) — tool_examples와 비교해서 참고할 만함 |
| 파생카드 생성 (확장/변형 공용) | `generateDerivedContent` | 기준정리 미착수. **알려진 버그 후보**: `highlightPhrases`가 answer 원문과 따옴표 등 구두점 차이로 못 찾아지면 조용히 드롭됨 (`deriveCard.js`의 `phrasesToHighlights`/`findIgnoringWhitespace`, 콘솔에 `[highlight] 답변에서 찾지 못한 문구라 하이라이트를 건너뜁니다` 경고로 실제 로그에서 확인됨). `findIgnoringWhitespace`는 공백만 무시하고 구두점은 무시하지 않음 — 이게 "연결/누락 오류" 트랙의 유력 후보이니 다음 세션에서 우선순위 높게 볼 것 |
| 직접작성 카드 추천 도구 생성 | `generateWriteContent` | 기준정리 미착수 |
| UX 평가 (전 카드 공용) | `generateUxEval` (`uxEval.js`) | 기준정리 미착수. `ai 수정 일의 순서` 메모(5번 항목)에 "확장/변형/직접작성/시작카드 전부 동일 system 프롬프트가 매번 통으로 재전송되는 문제"가 별도로 적혀 있음 — 이건 프롬프트 품질이 아니라 비용/구조 문제라 트랙이 다를 수 있음, 처리 방식 논의 필요 |

## 공통 문제 (모든 후속 호출에 걸쳐 있음, 아직 미해결)

**씨드카드 생성 이후 확장/변형/직접작성 단계로 넘어갈 때 `topic` 원문이 전달되지 않음.**

`deriveCard.js`의 `generateToolExamples`/`generateQuestion`/`generateDerivedContent`/`generateWriteContent` 전부 `cardDescription`/`parentDescription`(AI가 만든 문장)만 받고, 사용자가 최초에 입력한 topic은 어디에도 다시 주입되지 않음. 씨드카드 data에는 `topic` 필드가 이미 저장되어 있으므로(`CLAUDE.md` 카드 data 구조 참고), 전달 경로만 추가하면 되는 구조.

이 문제는 위 "아직 기준정리 안 된 대상" 각각을 개별로 고치기 전에, 한 번에 다룰지 각 호출 수정 시 같이 넣을지 방향을 먼저 정하는 게 좋음.
