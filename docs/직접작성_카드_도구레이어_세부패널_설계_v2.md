# 직접작성 카드 — 도구레이어 & 세부정보패널 설계 문서

> 이 문서는 새로운 대화 세션에서 작업을 이어나가기 위한 설계 기준서입니다.  
> 구현 시 AI 프롬프트 기준으로도 활용 가능합니다.

---

## 1. 시스템 개요

### 파생카드 생성 도구 3종

| 도구 | 방법론 | 설명 |
|------|--------|------|
| **확장하기** | BCC 사고도구 (11개) | 기존 아이디어의 구성요소를 분해·조합·연결·추가하여 새 아이디어 도출 |
| **변형하기** | ERRC 프레임워크 (4개) | 기존 아이디어의 요소 강도를 재조정(증가·감소·창출·제거)하여 시장 경쟁력 있는 형태로 전환 |
| **직접작성** | 없음 (사용자 직접 작성) | AI 방법론 개입 없이 사용자가 자유롭게 아이디어를 작성 |

### 파생카드 구조

각 파생카드는 **아이디어 레이어 + 도구레이어** 두 개의 레이어로 구성됩니다.

- **아이디어 레이어**: 카드의 아이디어 내용이 표시되는 메인 면
- **도구레이어**: 아이디어 레이어 아래에 깔려 있으며, 사용자가 아이디어 레이어를 클릭하면 도구레이어가 전면에 나타남

### 카드 타입별 도구레이어 성격

| 카드 타입 | 도구레이어 성격 | 역할 |
|-----------|---------------|------|
| 확장하기·변형하기 카드 | 과거형 (출처) | 이 카드가 어떤 도구로 만들어졌는지 설명 |
| **직접작성 카드** | **미래형 (추천)** | **다음 파생카드 생성 시 어떤 도구를 쓸지 추천** |

> **도구레이어 존재 이유**: 직접작성 카드는 활용 도구가 없어 도구레이어 콘텐츠가 없을 수 있으나, 파생카드는 카드 타입과 무관하게 모두 도구레이어를 가져야 씨드카드와 외형적으로 구분된다. 직접작성 카드는 과거 출처 대신 미래 추천으로 도구레이어를 채운다.

## 2. 확장하기 · 변형하기 정의 및 적용 기준

### 2-1. 확장하기 (BCC 사고도구)

**정의**  
기존 아이디어의 구성요소를 분해·조합·연결·추가하는 방식으로 새 아이디어를 도출하는 방법론.  
형태와 구조를 건드리는 접근.

**활용 BCC 11가지 도구**

| 도구 | 설명 |
|------|------|
| 제거 (Subtraction) | 당연히 있어야 한다고 생각했던 요소를 제거 후 새 가치 부여 |
| 용도통합 (Task Unification) | 두 개 이상의 기능을 하나의 요소에 통합 |
| 복제 (Multiplication) | 기존 요소를 약간 변형해서 추가 |
| 분할/분리 (Division) | 제품·시스템·서비스를 나누어 통제 가능하게 함 |
| 속성의존 (Attribute Dependency) | 외부 환경/조건과 내부 속성 간 상관성을 만들어 재구성 |
| 재정의 (Redefinition) | 고객과 핵심 요구사항을 새롭게 정의 |
| 결합 (Combination) | 두 개 이상의 요소·기능을 결합하여 새 가치 창출 |
| 연결 (Connection) | 관련 없는 두 요소를 결합하여 새 제품·서비스 고안 |
| 역전 (Reversal) | 요소의 위치·순서·핵심 속성을 반대로 하여 새 가치 창출 |
| 대체 (Replacement) | 구성 요소의 일부를 새로운 것으로 대체 |
| 유추 (Analogy) | 다른 시스템의 원리·기능·이미지에서 영감을 얻음 |

**확장하기가 맞는 카드 판단 기준**  
- 아이디어의 기능 구성이 불완전하거나 단편적인 상태
- 아직 연결되지 않은 구성요소나 빈 역할이 보이는 상태
- 기존 구조에 새로운 요소를 더하거나 조합하면 새 가치가 나올 여지가 큰 상태

---

### 2-2. 변형하기 (ERRC 프레임워크)

**정의**  
기존 아이디어에 있는 요소들의 강도를 재조정(높이거나·낮추거나·새로 만들거나·제거)하여 시장에서 경쟁력 있는 포지셔닝을 만드는 방법론.  
가치 요소의 비중과 방향을 건드리는 접근.

**ERRC 4가지 액션**

| 액션 | 질문 |
|------|------|
| 증가 (Raise) | 표준 이상으로 높여야 하는 요소는 무엇인가 |
| 감소 (Reduce) | 표준 이하로 낮추어야 하는 요소는 무엇인가 |
| 창출 (Create) | 새롭게 만들어야 하는 요소는 무엇인가 |
| 제거 (Eliminate) | 당연하다고 여겨지는 요소 가운데 빼야 하는 것은 무엇인가 |

**변형하기가 맞는 카드 판단 기준**  
- 아이디어의 기능 골격이 이미 갖춰진 상태
- 여러 기능이 나열되어 있으나 어느 것이 핵심 가치인지 선명하지 않은 상태
- 새 요소 추가보다 기존 요소들의 우선순위 재조정이 필요한 상태
- "이 서비스는 ○○ 때문에 쓴다"는 핵심 이유가 아직 불분명한 상태

---

### 2-3. 변별 핵심 기준 (한 줄 요약)

> **확장하기**: 이 아이디어의 문제가 **형태·구성의 부족**인가?  
> **변형하기**: 이 아이디어의 문제가 **가치 요소의 우선순위 불명확**인가?

## 3. 직접작성 카드 도구레이어 설계

### 3-1. 역할과 목적

- 사용자가 직접작성 카드를 선택하여 다음 파생카드를 만들려 할 때 툴바에서 확장하기·변형하기·직접작성 중 하나를 선택하게 됨
- 도구레이어는 그 선택을 돕기 위해 **확장하기·변형하기 중 어느 쪽이 이 카드 내용에 더 적합한지** 추천하고 그 이유와 기대효과를 제공
- 직접작성은 AI 개입이 없으므로 추천 대상에서 제외

### 3-2. 도구레이어 콘텐츠 구성

```
[추천방향] 확장하기 또는 변형하기 (아이콘 + 도구명)
[내용]
  - 첫 문장: 추천 이유 요약 (왜 이 도구인가 / 다른 도구를 배제하는 근거)
  - 둘째·셋째 문장: 기대효과 (이 도구를 고르면 무엇이 좋아지나)
```

**분량**: 3줄 이내  
**노출 원칙**: 상위도구명(확장하기·변형하기)만 노출. 세부도구명(제거·역전·복제 등 BCC 11개 / ERRC 4개 액션명) 절대 노출 금지 — 세부도구 선택은 모달에서 사용자가 직접 결정

### 3-3. 도구레이어 예시 데이터

**카드 내용**: 루틴 공유 커뮤니티  
*(나만의 루틴을 다른 사용자들과 공유하고, 비슷한 생활 패턴을 가진 사람들의 루틴을 참고할 수 있는 기능. 직장인, 수험생, 육아맘 등 라이프스타일 태그를 기반으로 검색하고 마음에 드는 루틴을 내 앱에 바로 적용할 수 있다.)*

```
추천방향: 변형하기
아이콘: transform

내용:
이 아이디어는 기능 구성이 이미 갖춰진 상태입니다.
무엇을 더 밀고 무엇을 덜어낼지 재조정하면,
이 앱만의 경쟁력 있는 포지션이 선명해질 수 있습니다.
```

## 4. 직접작성 카드 세부정보패널 설계

### 4-1. 역할과 목적

- 도구레이어의 추천을 **납득**시키는 면
- 도구레이어가 요약한 추천 이유를 더 상세하게 풀어서 설명
- 사용자가 "왜 이 도구인가"를 충분히 이해할 수 있도록 근거를 구체화

### 4-2. 세부패널 콘텐츠 구성

```
[아이디어 출처]
  - 부모카드명 (이 직접작성 카드가 파생된 원본 카드)

[추천도구]
  - 추천방향: 확장하기 또는 변형하기 (아이콘 + 도구명 + 서브라벨)
  - 추천 이유:
      도구 정의를 한 문장으로 압축한 뒤,
      이 카드의 구체적 문제와 도구가 어떻게 연결되는지 설명
```

**노출 원칙**: 도구레이어와 동일하게 상위도구명만 노출. 추천 이유에서 도구를 설명할 때도 세부도구명·세부 액션명 언급 금지

**도구레이어와의 관계**: 도구레이어는 추천 이유 + 기대효과를 요약 제공. 세부패널은 도구 정의 + 이 카드에 맞는 구체 이유를 상세 제공. 같은 맥락이나 깊이가 다르며 문장이 겹치지 않도록 한다.

### 4-3. 세부패널 예시 데이터

**카드 내용**: 루틴 공유 커뮤니티 (동일 카드)

```
아이디어 출처:
  부모카드: AI 생활 루틴 코치 앱

추천도구:
  추천방향: 변형하기
  서브라벨: 기존 요소의 강도를 재조정하는 방향

  추천 이유:
  변형하기는 기존 요소 중 무엇을 더 밀고 무엇을 덜어낼지
  질문하는 방법론입니다. 공유·태그 검색·즉시 적용이 동등한
  비중으로 나열되어 있어 이 서비스를 쓰는 핵심 이유가
  선명하지 않은 지금, 구성 요소를 추가하는 것보다 기존
  기능들의 우선순위를 재조정하는 것이 필요한 다음 단계일
  수 있습니다.
```

## 5. AI 생성 프롬프트 기준

### 5-1. 도구 선택 판단 프롬프트

구현 시 AI가 확장/변형 중 어느 쪽을 추천할지 판단하는 기준 프롬프트입니다.

```
당신은 아이디어 발전 도구를 추천하는 AI입니다.
아래 아이디어 카드 내용을 분석하여 확장하기와 변형하기 중
더 적합한 도구를 하나만 선택하고 그 이유를 설명하세요.

[판단 기준]
- 확장하기(BCC 사고도구): 아이디어의 기능 구성이 불완전하거나
  단편적일 때. 새로운 구성요소를 더하거나 기존 요소를 조합·연결할
  여지가 클 때.
- 변형하기(ERRC 프레임워크): 아이디어의 기능 골격이 이미 갖춰져
  있으나 요소 간 우선순위가 불분명할 때. 어떤 요소를 더 강조하고
  무엇을 덜어낼지 재조정이 필요할 때.

[절대 금지]
- 확장하기·변형하기 외 다른 도구명 언급 금지
- BCC 세부도구명(제거·복제·역전 등) 언급 금지
- ERRC 세부 액션명(증가·감소·창출·제거) 언급 금지
- 두 가지를 동시에 추천하거나 "둘 다 가능하다"고 답하는 것 금지

[출력 형식]
추천도구: [확장하기 또는 변형하기]
판단 이유: [이 카드의 구체적 문제를 근거로 왜 이 도구인지,
다른 도구를 배제하는 이유 포함, 2~3문장.
도구레이어·세부패널 생성의 입력값으로 사용되므로
카드 내용에 밀착한 구체적 언어로 작성]

[아이디어 카드 내용]
{card_content}
```

### 5-2. 도구레이어 콘텐츠 생성 프롬프트

```
당신은 아이디어 카드의 도구레이어 텍스트를 작성하는 AI입니다.
아래 정보를 바탕으로 도구레이어에 들어갈 내용을 작성하세요.

[도구레이어의 역할]
사용자가 이 카드를 보고 다음 파생카드 생성 도구를 선택할 때
빠른 판단을 돕는 면입니다. 추천 이유(왜 이 도구인가)와
기대효과(이 도구를 고르면 무엇이 좋아지나)를 담습니다.

[작성 기준]
- 분량: 3줄 이내
- 첫 문장: 추천 이유 요약 — 이 카드의 현재 상태와 왜 해당 도구가
  맞는지 (다른 도구를 배제하는 근거 포함)
- 둘째·셋째 문장: 기대효과 — 추천 도구를 선택했을 때
  이 아이디어가 어떻게 발전할 수 있는지
- 확장하기·변형하기 도구명만 사용. 세부도구명 절대 언급 금지
- 단정적 표현("~됩니다") 대신 가능성 표현("~될 수 있습니다",
  "~여지가 생깁니다") 사용
- 카드 내용에 밀착한 구체적 언어 사용. 어느 카드에도 쓸 수 있는
  범용 문구 금지

[입력 정보]
추천도구: {tool_name}
아이디어 카드 내용: {card_content}
```

### 5-3. 세부정보패널 콘텐츠 생성 프롬프트

```
당신은 아이디어 카드 세부정보패널의 추천도구 섹션 텍스트를
작성하는 AI입니다.
아래 정보를 바탕으로 세부패널 추천 이유 텍스트를 작성하세요.

[세부패널의 역할]
도구레이어에서 요약한 추천 이유를 더 깊이 납득시키는 면입니다.
사용자가 "왜 이 도구인가"를 충분히 이해할 수 있도록
도구 정의와 이 카드의 구체적 문제를 연결하여 설명합니다.

[작성 기준]
- 추천 이유 단일 단락으로 작성
- 첫 문장: 추천 도구가 어떤 방법론인지 한 줄로 정의
- 이후 문장: 이 카드의 구체적 문제와 도구가 어떻게 연결되는지 설명.
  카드 내용의 구체적 요소(기능명, 구조 등)를 직접 지목할 것
- 세부도구명(BCC 11개·ERRC 4개 액션명) 절대 언급 금지
- 단정적 표현 대신 가능성·판단 표현 사용
```

## 6. 핵심 설계 원칙 요약

| 원칙 | 내용 |
|------|------|
| 단일 추천 | 확장·변형 중 하나만 추천. 둘 다 제시하지 않음 |

| 요약·상세 관계 | 도구레이어와 세부패널은 같은 맥락이나 깊이가 다름. 문장 중복 금지 |
